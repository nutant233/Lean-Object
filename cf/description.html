Lean Object makes Minecraft's most-used lookup objects cheaper, by deduplicating them. When a value exists exactly once, comparing it becomes a pointer compare instead of a string compare — and that comparison happens on every registry lookup, tag check and ingredient match.

For Minecraft 1.20.1 / Forge. Requires Java 17.

Why deduplication makes things faster

A hash code only picks the bucket. Every collision inside that bucket is then resolved with equals(), and that is where the expensive work happens — for a TagKey, comparing a ResourceKey and a ResourceLocation, i.e. string chains. Modded packs make this worse: thousands of identifiers sharing prefixes like minecraft: or mymod: have hash codes that cluster, so the buckets where comparisons pile up are exactly the busy ones.

Keep only one instance per logical value, and equals can be reduced to o == this and hashCode to System.identityHashCode. Every one of those comparisons becomes a pointer compare. Less memory is a side effect of the same change, not the goal.

Features

All features are on by default and can be switched off individually in config/leanobject.toml.

FeatureWhat it does
ResourceLocation Interns namespace, path and model variant strings, so duplicate strings for the same id are shared.
TagKey Custom interning replaces the vanilla interner, and equals/hashCode become identity based. Tag membership tests are the hottest path in most packs.
ResourceKey Same treatment for registry keys, plus faster creation.
Ingredient Single-entry ingredients reuse one shared instance, so recipes stop rebuilding identical Ingredient objects and their lazily built item arrays.
NBT containers Replaces the maps and lists inside CompoundTag, ListTag and NBT record building with leaner equivalents.
Model objects Leaner containers for baked block and item models. Client side.
AE2 storage keys Deduplicates AE2 AEItemKey / AEFluidKey. Requires AE2.
Farmer's Delight Caches tool action ingredients parsed from recipe JSON and packets. Requires Farmer's Delight.

Playing a tech pack? Turn on AE2 key deduplication

Official AE2 has no interning for storage keys — AEItemKey's constructor and its factory are both private, so every lookup builds a new key object. A late-game ME network is little but keys: banks of interfaces, storage buses, import/export buses and crafting CPUs hold enormous numbers of them, all allocated on demand and compared by value.

That is exactly the workload this feature targets, and it speeds up key creation, not just key lookup:

  • Vanilla allocates a new key object and computes its hash on every single lookup — the constructor calls Objects.hash(...) and stores the result.
  • With this mod, a key without NBT becomes a field read: the shared instance is fetched from the item, with no allocation and no hashing at all.
  • A key with NBT costs one hash lookup keyed by the NBT, and that is the entire cost. Only the first lookup for a given tag allocates anything; repeats return the existing key.
  • With keys existing once, comparisons become reference checks — which is what a large network spends its time on.

In a modded pack this happens constantly. AE2 rarely works on its own storage: storage buses, import and export buses and interfaces connect the ME network to other mods' inventories — chests, barrels, machines, drawers, pipes — and every item moved across that boundary is converted between an ItemStack and an AE key. Those transfers run continuously in bulk, per item, per bus, per tick. A shared instance per logical key turns that conversion into a cache probe instead of an allocation plus a hash.

Supersedes Fast Tag

Lean Object replaces Fast Tag and is meant to be used instead of it. The TagKey and ResourceKey features are a direct port — the same methods are replaced, with the same reasoning, and interning keys are compared by reference in both. What changed is the cache backend: Fast Tag used Guava's MapMaker and reflection into its internals, Lean Object uses its own caches with plain identity maps and no reflection.

Do not install both. They replace the same methods, and the last one applied wins.

Configuration

config/leanobject.toml is regenerated on every launch:

enabled = true          # master switch
loggingInGC = true      # force a GC and log heap usage when joining a world

[features.tagKey]
    safeMode = false    # false = replace the method, true = wrap the original
    enabled = true

safeMode only applies to features that ship a non-destructive variant (resourceKey and tagKey). Set it to true if another mod conflicts with the replacement path — it wraps the original method instead of replacing it, which is more compatible but slightly slower.

Compatibility notes

  • Injection conflicts. Most features replace methods outright. If another mod modifies the same target, the two fight and the last one applied wins. The model feature in particular is known to conflict on large packs; it can be turned off on its own.
  • Reference equality. Interned keys compare by reference, so a value created outside the interning entry points will not compare equal to its interned twin.
  • AE2 support is version specific. It targets official AE2 15.4.10. Forks or other builds can change the internals it hooks, in which case the feature simply stops applying.
  • Optional integrations are auto-detected. Features whose mod is not installed are skipped automatically.
  • ResourceLocation interning costs CPU as well as saving memory. ResourceLocation is constructed extremely often, and interning adds a hash plus a lock-guarded table lookup to every construction. It pays off when the same id is created repeatedly; it can cost CPU on hot paths that keep producing distinct ids, where nothing gets shared. If you are chasing CPU rather than memory, try turning this one feature off first.
